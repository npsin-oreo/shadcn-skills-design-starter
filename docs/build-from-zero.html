Phase 2 · the source of truth

Tokens (DTCG, 3-tier)

Tokens live in tokens/*.tokens.json and generate the CSS — never hand-edited.

prompt · skills: design-tokens, token-build
Using design-tokens + token-build: pull the Figma variables and author them as
DTCG tokens in tokens/ with the 3-tier architecture (primitive → semantic →
component), split into color, dimension, typography, motion. Write
scripts/build-tokens.mjs → app/tokens.generated.css, where semantic aliases resolve
to var(--role) so they stay light/dark aware. Wire "tokens:build" and make "build"
run it first. Semantic vars must alias primitives, never hold raw values.
Produces
  • tokens/*.tokens.json ×4
  • build-tokens.mjs
  • tokens.generated.css
Gate 2

✓ tokens:build reproducible (no diff on re-run — CI enforces) · semantics alias primitives.

output tokens/color.tokens.json
"primitive": {
  "blue": { "action": { "$value": "#0071e3" } }
},
"semantic": {
  "primary": { "$value": "{primitive.blue.action}" }
}

Why now: components bind to these token names. Build a component before its token exists and it hardcodes a value — the exact thing CI later fails on.

Field notes

The traps that cost the most time

Two Figma channels aren't interchangeable. REST reads structure; variable values are Enterprise-only over REST — use MCP get_variable_defs. Writes go through the Plugin API, never REST.
A committed variables-export.json goes stale. Trust live Figma (MCP) for parity — the snapshot can drift from the live file after a brand re-point.
A raw node dump over-reports drift. Colours on visible:false nodes and instance interiors don't render — filter them, or you'll "fix" things nobody sees.
Variant audits attribute per-page, not per-component. A Type=Outline found on the Spinner page may belong to a Button composed there. Open the node before "fixing."
Tokens are generated. Edit tokens/*.json then tokens:build — never hand-edit the generated CSS (CI fails on drift). PATs expire; keep the live one in gitignored .env.local.
